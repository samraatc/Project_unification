1. Executive Summary
This document is the consolidated master plan for the Unified Marketing and E-Commerce Management
Platform — a single, role-controlled web application that brings together five tightly integrated capabilities
into one product:
   Centralised social media control across Facebook, Instagram and TikTok — compose once, publish
    everywhere, reply from a single inbox.
   A full e-commerce engine with product catalogue, cart, checkout, multi-gateway payments (eSewa,
    Khalti, card) and customer self-service.
   End-to-end order tracking and inventory management — every sale auto-deducts stock, every return
    auto-restocks, every status change auto-notifies.
   Granular Role-Based Access Control with Super Admin, Admin, Editor, Accountant, Viewer and
    unlimited custom roles.
   A premium Accounting & Audit module unlocked via monthly, yearly or lifetime subscription — full
    double-entry ledger, VAT/GST, immutable audit trail and regulator-ready reports.
The platform replaces 5–7 separate SaaS tools that businesses typically stitch together (a social scheduler,
an inbox tool, a storefront platform, an order/inventory app and an accounting system). By consolidating
them into one product with a shared identity layer, RBAC engine and database, it eliminates duplicate data
entry, removes integration drift, and gives leadership a single source of truth across marketing, sales,
fulfilment and finance.

2. Project Objectives & Scope
2.1 Business Objectives
   Eliminate tool fragmentation by consolidating social media management, e-commerce, fulfilment and
    accounting into one platform.
   Increase team productivity through role-based workspaces that surface only the tools and data each
    user needs.
   Enable data-driven decisions by unifying analytics across social channels, sales, inventory turnover and
    finance.
   Open a recurring-revenue stream by offering the Accounting module as a paid, subscription-gated add-
    on (monthly / yearly / lifetime).
   Ensure security and compliance — robust authentication, immutable audit logging, RBAC enforcement,
    GDPR-aligned data handling.
   Scale gracefully to multi-warehouse, multi-currency and additional social channels without re-
    architecting.

2.2 In Scope
   Public storefront with full catalogue, cart and checkout.
   Customer profile, address book, wishlist, order history and tracking.
   Admin web console for social, catalogue, orders, inventory, CRM, finance.
   Payment integrations: eSewa, Khalti, Stripe (card), Cash-on-Delivery.
   Social integrations: Meta Graph API (Facebook + Instagram), TikTok API.
   Premium Accounting module with subscription paywall.
   Mobile-responsive (PWA) — no native mobile apps in this phase.
   Cloud deployment (AWS or GCP), CI/CD, monitoring and backups.

2.3 Out of Scope (this release)
   Native iOS / Android apps (planned for Phase 2 / Year 2).
   B2B wholesale portal with negotiated pricing tiers (future enhancement).
   Physical POS hardware integration in retail stores (future enhancement).
   Marketplace functionality (multi-vendor sellers) — single-tenant only.

4. Role-Based Access Control (RBAC)
RBAC is a foundational, cross-cutting layer of the platform. Every API route is guarded by middleware that
checks the caller's role(s) and permission(s) before processing the request. Roles can be created, modified
and assigned by Super Admins (and by Admins for any role below them).

4.1 Role Definitions
      Super Admin — unrestricted access; the only role allowed to manage other Super Admins, change
       system settings, configure billing / Stripe Connect, and purge audit logs.
      Admin — full operational control: social, e-commerce, CRM, analytics, user management for non-admin
       roles; cannot modify Super Admins or system-level configuration.
      Editor — content & catalogue: publish on social, edit products, update order status; no access to
       finance or user management.
      Accountant — finance focus: view revenue, invoices, payouts, reconciliation, exports; gateway to the
       premium Accounting module if subscribed.
      Viewer — read-only analytics for stakeholders / investors / juniors.
      Custom Roles — Super Admins and Admins can compose roles from individual permissions (e.g. 'Social
       Media Manager' = posting + analytics, no e-commerce).

5. Premium Module — Accounting, Tax & Audit
(Subscription-Gated)
This is a paid add-on. Out of the box, every tenant receives the operational platform (sections 3 and 4). The
Accounting, Tax and Audit module is subscription-gated and unlocks a complete double-entry accounting
suite, tax computation and an immutable audit trail.

5.1 Why It's Premium
   Replaces a separate accounting subscription (Tally / QuickBooks / Xero / Zoho) — so the willingness-to-
    pay already exists in the customer's budget.
   Reduces double data entry by sourcing journal entries directly from real-time platform events (orders,
    refunds, payouts, inventory write-offs).
   Provides regulator-ready VAT / GST returns and audit packs — a compliance lifeline that justifies
    recurring fees.
   Creates predictable MRR / ARR for the platform vendor and a high-margin expansion path beyond the
    base seat licence.

5.2 Feature Set
5.2.1 Double-Entry Ledger
   Configurable Chart of Accounts (CoA) — pre-loaded templates for Retail, Services and Manufacturing;
    editable.
   Auto-generated journal entries from platform events — each order, refund, payout reconciliation, stock
    write-off and PO receipt posts the correct debits and credits.
   Manual journal entry interface for adjustments, accruals, depreciation.
   Multi-currency support with daily FX rates; settlement currency configurable.
   Period close: monthly / quarterly / yearly close with locking and reopening controls (Super Admin only).

5.2.2 Tax Module
   VAT / GST configuration per product or product category.
   Tax computation at cart and invoice level; correct treatment of inclusive vs exclusive pricing,
    exemptions and zero-rated items.
   Tax-period returns: VAT 200 / GST returns in regulator-ready format; Nepal IRD (Inland Revenue
    Department) e-invoice JSON export.
   Withholding-tax handling on supplier payouts and commissions.
   Tax-jurisdiction routing for international orders (placeholder for future OECD / DST changes).

5.2.3 Reports & Statements
   Profit & Loss (monthly, quarterly, yearly, custom range).
   Balance Sheet with comparative periods.
   Cash-flow statement (direct or indirect method).
   Trial balance, general ledger, sub-ledger drill-down.
      Aged receivables and payables.
      Inventory valuation report (FIFO, weighted-average, configurable).
      All reports exportable as PDF / Excel; scheduled email delivery option.

5.2.4 Audit Trail
      Immutable, append-only audit log of every accounting event — who, when, what, before / after values,
       source (UI, API, automation).
      WORM-style storage (write-once-read-many) to satisfy auditor requirements.
      Audit pack export: zip of trial balance + GL + audit log + supporting documents, signed with a
       cryptographic hash for tamper-evidence.
      Read-only auditor user role — external auditor can be invited with time-bounded access, scoped to one
       fiscal year.

5.2.5 Bank Reconciliation
      Import bank statements (CSV / OFX / direct API where available).
      Auto-match rules engine with confidence score; manual override.
      Outstanding-items report; reconciliation lock when complete.

5.2.6 Budgeting & Forecasting
      Annual budget setup per cost centre / department.
      Actual-vs-budget variance reports with drill-down.
      Cash-flow forecast using payment terms and historical conversion patterns.

5.4 Feature Gating Logic
   A central Subscription & Billing Engine stores each tenant's active plan, expiry date and feature
    entitlements as a JSON blob.
   Every accounting API route checks: (1) authenticated user, (2) RBAC role allows accounting, (3) tenant
    has an active entitlement covering that feature.
   UI components in the Accounting Portal are rendered conditionally on entitlements — locked features
    show an upgrade prompt rather than an error.
   Grace period of 7 days on expiry — read-only access, prevents data loss; after 14 days the data is
    archived (export available on reactivation).
   Lifetime plan is bound to a major version; major upgrades are sold separately at 50% of the then-
    current lifetime price.

5.5 Billing & Payment for the Subscription
   Stripe Billing (international cards), eSewa and Khalti subscriptions (NPR market) — recurring charge
    handled by the payment gateway.
   Auto-invoice generation in the customer's name, with VAT line where applicable.
   Dunning workflow on failed renewals: retry on day 1, 3, 7; downgrade automatically on day 14.
   Customer-facing self-service: change plan, update card, download invoices, cancel subscription with
    reason capture.

5.6 Compliance & Regulatory Mapping (Nepal-first)
   Nepal IRD: PAN integration, e-invoice JSON, VAT 200 return format.
   Indian GST (when expanding): GSTR-1 and GSTR-3B export.
   International readiness: IFRS-style P&L and Balance Sheet formats included.
   Data residency: tenant data can be pinned to a specific cloud region (Enterprise plan).

7. End-to-End System Flow
The flow diagram on the next page shows how an end-to-end customer purchase moves through the
system, alongside the parallel administrative and accounting workflows that get triggered automatically.




                             Figure 2 — End-to-End System Flow (Swim-Lane View)

7.1 Walkthrough — A Typical Purchase
1. Customer registers (or logs in) on the storefront — Auth & RBAC service issues a JWT.
2. Customer browses the catalogue (served from PostgreSQL via Elasticsearch) and adds items to their
   cart (cached in Redis).
3. At checkout, the Order Service creates a Pending order, the inventory service reserves stock, and the
   Payment Orchestrator initiates the selected gateway (eSewa / Khalti / Stripe).
4. On payment verification, the State Machine transitions the order to Confirmed, fires Email + SMS +
   Push notifications, and posts a journal entry to the Accounting Core (if the tenant has a Premium
   subscription).
5. Admin sees the order in real time via WebSocket; assigns courier; the courier webhook later pushes
   Out-for-Delivery and Delivered events.
6. Customer can track the order live, raise a return inside the return window, or rate the product after
   delivery.
7. Returns and refunds reverse the stock and post the offsetting journal entries, keeping inventory,
   finance and customer records consistent.
7.2 Cross-Cutting Concerns
   Every cross-lane arrow in the diagram is an authenticated, RBAC-checked API call.
   Every status change broadcasts via WebSocket to relevant dashboards in real time.
   Every business event is appended to the immutable audit log.
   Premium-gated calls go through an entitlement check before executing.

8.1 Security Architecture
   Authentication: short-lived JWT access tokens + rotating refresh tokens; OAuth 2.0 for social login; 2FA
    (TOTP) enforced for Super Admin and Admin.
   Authorization: every API route guarded by RBAC middleware; entitlement check for premium routes.
   Encryption: AES-256 at rest, TLS 1.3 in transit, secrets in Vault / KMS.
   Audit logging: every CRUD action captures user, timestamp, IP and payload diff.
   Rate limiting and brute-force lockout on auth endpoints.
   Periodic dependency scanning (Dependabot / Snyk), third-party pen test pre-launch, annual re-test
    thereafter.
   PCI scope minimisation: card data never touches our servers (Stripe Elements).
   Data privacy: GDPR-aligned consent, data export, right-to-deletion flows.

13.1 Operational KPIs
   Order processing time from payment confirmation to dispatch — target < 4 hours.
   Cart-to-checkout conversion rate — target > 35%.
   Checkout-to-paid conversion rate — target > 75%.
   Average order-tracking events delivered per order — target ≥ 5.
   Customer support ticket resolution time — target < 24 hours median.

13.2 Marketing KPIs
   Time saved per week on social management — target ≥ 40% vs manual tool switching.
   Social engagement rate uplift — target +20% within 90 days post-launch.
   Cross-channel post-failure rate — target < 0.5%.

13.3 Technical KPIs
   Platform uptime — target 99.9% monthly.
   p95 API latency — target < 300 ms.
   Zero critical security incidents in first 12 months post-launch.
   Deployment frequency — target weekly to production.

13.4 Premium / Commercial KPIs
   Free-trial-to-paid conversion — target ≥ 20%.
   Monthly recurring revenue (MRR) — target USD 25k by month 6 post-launch.
   Churn — target < 4% monthly.
   Net revenue retention — target > 105%.
